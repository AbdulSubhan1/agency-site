# Engineering highlights

What this project does beyond "it works", and why.

| Decision                                                                                                                                                                                                                                                                                               | Why                                                                                                                                                                                                                                   | Where                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **One codebase, two brands, chosen at build time.** Each Vercel project sets `BRAND`; an unknown value fails the build.                                                                                                                                                                                | Both brands share every page, form and fix, while each keeps its own tone, prices and look. Choosing at build time (not by hostname) keeps every page static and makes a wrong deploy fail loudly instead of showing the other brand. | `src/lib/brand.ts`, `brand.test.ts`                                           |
| **No database on the website.**                                                                                                                                                                                                                                                                        | Leads belong in the CRM. The site holds no customer data and no database credentials, so a site breach exposes nothing.                                                                                                               | `AGENTS.md`                                                                   |
| **Content is typed data with a per-brand override layer.** Nine services and five products live once in `src/content/`; each brand file sets only what differs: positioning, tone, hero and CTAs, the featured order per region, industries, currency, time zone, spelling, service wording and theme. | Both brands sell the same work, so one fix to a service updates both sites. A brand can't drift into a half-copied page, and adding a region (Saudi Arabia later) is one entry in a brand file.                                       | `src/content/`, `src/brands/`, `src/content/resolve.ts`                       |
| **The tests guard the content.** Every service is checked against a zod schema and must have a price, or an explicit "not offered", for every region. A brand may only feature services priced in that region, and may only show products whose follow-up service is offered there.                    | Content changes more often than code and is edited by non-developers. A missing price or a featured service with no price fails `npm test` instead of showing "undefined" on a live page.                                             | `src/content/content.test.ts`                                                 |
| **One spelling source.** Shared copy is written in US spelling; the UK brand swaps a short word list at render time, and a test fails if UK spelling slips into the shared copy.                                                                                                                       | Two copies of every sentence would drift. A short list plus a test keeps one source and correct spelling for each market.                                                                                                             | `src/lib/spelling.ts`                                                         |
| **Prices are numbers, formatted per brand.** Ranges are stored as whole numbers in the region's currency and formatted with `Intl` (`$2,500–5,000`, `AED 3,500–9,000`).                                                                                                                                | Prices can be compared, sorted and checked by tests, and a currency's format is never typed by hand.                                                                                                                                  | `src/lib/money.ts`                                                            |
| **Motion with GSAP, one module.** ScrollTrigger and SplitText (free since GSAP 3.13) come from `src/lib/gsap.ts`, and every section animates inside `useGSAP` with `gsap.matchMedia`.                                                                                                                  | `useGSAP` cleans up on unmount, so pinned sections don't leak between pages. `matchMedia` makes "reduce motion" a first-class state: with it on, every section renders final and readable.                                            | `src/lib/gsap.ts`, `src/components/home/`                                     |
| **Scroll stories are data, not code.** The hero visual, the evening feed and the before/after story come from each brand's `showcase`; the components only animate them.                                                                                                                               | The US brand tells a workday story and the Asia brand an order's journey with the same components. A new region's example is an edit in a brand file.                                                                                 | `src/brands/*.ts`, `src/brands/types.ts`                                      |
| **Pin only where it fits.** Pinned, scrubbed sections run from tablet width up; on phones the same timeline plays once when it scrolls into view.                                                                                                                                                      | Pinning content taller than the screen hides its end (the fourth order step on a phone).                                                                                                                                              | `story-day.tsx`, `story-flow.tsx`, `services-rail.tsx`                        |
| **Brand colours as CSS variables.** The root layout writes the brand's theme to `<html>`, and Tailwind's `@theme inline` maps them to classes (`bg-night`, `text-accent`).                                                                                                                             | One component set, two looks, no per-brand CSS files; the theme lives next to the rest of the brand's settings.                                                                                                                       | `src/app/layout.tsx`, `src/app/globals.css`                                   |
| **Examples are labelled.** Every worked example says "Example" and the footer says they are illustrations.                                                                                                                                                                                             | No client results exist yet, and the rule is that every number shown comes from a real project.                                                                                                                                       | `src/brands/*.ts`, `src/app/page.tsx`                                         |
| **Enquiries are signed server to server.** The form posts to a server action, which checks it again and signs the call to AgencyDesk with HMAC-SHA256 over the timestamp, method, path and body. A test pins the CRM's fixed signature vector.                                                         | The secret never reaches the browser, a copied request expires after 5 minutes, and if either side changes how it signs, both test suites fail.                                                                                       | `src/lib/signature.ts`, `src/lib/agencydesk.ts`, `src/app/contact/actions.ts` |
| **One schema for the browser and the server.** The same zod rules check the form before it's sent and again in the server action; the CRM's answer for a bad field shows under that field too.                                                                                                         | The visitor sees the same message whichever side catches the problem, and a hand-made request can't skip the checks.                                                                                                                  | `src/lib/lead-form.ts`                                                        |
| **Each brand asks in its own way.** US: two steps (what you need, then who you are) and a work email. Asia: WhatsApp number first with the opt-in tick, and the calling code decides UAE or Pakistan.                                                                                                  | US buyers expect email and a booked call; in the UAE and Pakistan WhatsApp is the main channel, and WhatsApp's policy needs an opt-in.                                                                                                | `src/components/contact/lead-form.tsx`                                        |
| **The form is sent by hand, not through the form's `action` prop.**                                                                                                                                                                                                                                    | React resets a form after its action, which would wipe what the visitor typed whenever the server sends a field back to fix.                                                                                                          | `src/components/contact/lead-form.tsx`                                        |
| **The contact form renders inside Suspense.**                                                                                                                                                                                                                                                          | `cacheComponents` prerenders every page; the query (`?service=`, `?product=`) is only known per request, so only the form waits for it and the rest of the page stays static.                                                         | `src/app/contact/page.tsx`                                                    |
| **Every CRM call is reported to Pulse** (route, status, time, never the body), and the beacon loads once the site is registered there.                                                                                                                                                                 | A failing form shows up in monitoring before a visitor complains.                                                                                                                                                                     | `src/lib/pulse.ts`, `src/app/layout.tsx`                                      |
